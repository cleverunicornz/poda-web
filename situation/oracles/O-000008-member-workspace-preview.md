# Oracle for the member-workspace preview

## State

designed

## Judges

[P-000008](situation/promises/P-000008-member-workspace-preview.md)

## Inputs

Before observation, a separately authorized qualification must supply a finite
dossier identifying the exact candidate revision and consumed Element/Module
API version, browser/version, preview/test activation and disabling procedure,
existing Storybook entries and Element-hosted integration entrypoint. It must
name:

- The complete Chat/Studio/Profile/Settings navigation and Podcasts,
  Episodes, Analytics, own-profile and creators-directory/detail inventory;
  read-only creator browsing, exact registered locations and query/direct-entry cases, a
  back/forward sequence, an unknown-location case and a Matrix deep link,
  each with an expected destination. Alpha location registration does not
  establish arbitrary nested-route support.
- The shared typed fixture/scenario revisions, a publication-cleared mapping
  of the agreed editor coverage to manual interactions, and a representative
  editable form and Analytics view with their selected conversation-adjacent
  host. Retain full submitted coverage privately for review; this input is
  not permission to publish donor field tables or a mandated backend schema.
  Coverage omissions require an explicit scope decision, not a smaller demo.
- Named new-podcast/new-episode draft create/accept/discard and collection/detail
  revisit sequences, existing-artifact editing and analytical selection/result
  updates, initial and resulting visible states, and how to reset them.
  Identify the shared domain components and view contracts for bounded reuse
  review; do not require a file count, code layout, copied fields or a new
  fixed interface.
- Named loading, empty, invalid-input and rejected-action sequences; a clean
  incoming-artifact update; an incoming update while a human draft is dirty;
  and an away/return dirty-draft sequence. Predeclare input preservation,
  update observation and explicit draft adjudication expectations as preview
  scenarios, not selected production autosave/merge/approval policy.
- Two explicitly permitted Matrix fixture room identities, the existing
  member session, and native room-select/send/edit/reply, room-switch,
  pane-mount/unmount and return-to-Chat sequences. Identify visible-room
  registration and lifecycle expectations for the selected exported native
  RoomView host. Conversation messages and product-artifact updates are
  separate inputs; no assistant provisioning or real tool execution is needed.
- The Settings open/change/close interaction and invoking context, using
  the native UserSettingsDialog; the exact setting and its expected native
  result must be selected before observation.
- Poda Light and Poda Dark at 1440 × 900 and 500 × 900 for every inventory
  page and both representative views in both hosts. Name keyboard-only
  journeys through navigation, form validation/correction/acceptance,
  Analytics selection, conversation entry/exit and Settings close/return,
  including expected focus targets and accessible names.
- A preview-disabled entry and a product-service-unavailable case, with
  expected absence of simulated product fallback and false real-success
  claims. Distinguish Matrix fixture-service traffic/results from simulated
  product state. No production build or default Matrix fixture alone decides
  this boundary.

The observer retains direct visual/interaction evidence and the relevant
bounded source/configuration review for each leg on that revision. Expectations
must precede the observation that judges them. Missing, invalid, inaccessible or
unselected required fixtures, permissions, contracts, policies or instruments
make the affected leg **blocked / not judged**. They are not an observed FAIL,
and an absent observation is never a PASS. Record the unavailable input and
affected legs; retain mixed observed outcomes without inventing results.

## Pass

A complete PASS requires every P leg and adequate direct evidence deciding
every F leg false. P1–P13 correspond to Promise clauses 1–13:

- **P1** — Every inventory entry is reachable through the proposed navigation;
  the named lists/details, own-profile editing and read-only creator browsing
  behave as declared without chat or assistant invocation.
- **P2** — The agreed coverage mapping is exercised across podcast, episode
  and own-profile editors: new podcast/episode drafts, valid edits, validation,
  explicit preview acceptance/discard and collection/detail revisits behave
  as predeclared, without suggesting real persistence.
- **P3** — The representative form works in both selected hosts with
  equivalent visible identity, validation and action outcomes. Bounded
  component/view-contract review establishes reuse of the same domain form,
  not independent editors that merely resemble each other.
- **P4** — The representative Analytics view works in both selected hosts
  using the same domain view/contract; the declared selection and result
  updates agree and remain visibly simulated.
- **P5** — The existing Storybook catalogue and Element integration preview
  use the shared typed scenarios; observed edits and analytical actions
  actually transition visible state rather than only logging calls or
  retaining an unchanged static snapshot.
- **P6** — Loading, empty, invalid-input and rejected-action scenarios show
  their expected state; correction input survives validation/rejection and
  no rejected action appears accepted or saved.
- **P7** — Clean and dirty incoming-update sequences and dirty away/return
  behavior match the declared expectations. Artifact updates are distinct
  from conversation text, and a human draft survives or receives the
  predeclared explicit adjudication without silent replacement.
- **P8** — Native room-select/send/edit/reply and the declared switch,
  mount/unmount and return sequences preserve the supplied room identity and
  member session, with no stale-room display or second login.
- **P9** — Settings opens the native UserSettingsDialog, the selected
  interaction has its declared native result, and closing restores the
  invoking context and focus rather than leaving a replacement settings page.
- **P10** — Every declared location/query/direct-entry/history/unknown-route
  and Matrix-deep-link case reaches its expected context within Element's
  member navigation lifecycle.
- **P11** — Every declared page/host/theme/viewport case has readable content,
  reachable primary actions and visible state messages without obstructive
  clipping or overlapping chrome.
- **P12** — Every declared keyboard journey exposes labelled reachable
  controls, visible focus, usable validation feedback and expected focus
  restoration, with no unintended trap.
- **P13** — Selected previews are visibly simulated, and both declared
  preview-disabled/service-unavailable cases exclude product-fixture fallback
  and false saved/published/assistant-success claims. Matrix fixture results
  are not presented as real product outcomes.

## Fail

An observed in-Scope contradiction with valid required inputs is a FAIL.
Unobserved or blocked legs prevent a complete PASS but are not failures:

- **F1** — A required inventory entry or declared conventional navigation
  journey is missing, unusable, violates the declared read-only creator
  presentation, or requires chat/assistant invocation.
- **F2** — A mapped create/edit/accept/discard/collection/detail-revisit
  interaction loses its expected state, fails its declared validation
  behavior, or represents preview acceptance as real persistence.
- **F3** — The representative form cannot be used in either host, diverges
  on identity/validation/action outcomes for equivalent scenario inputs, or
  is implemented as independent host-specific domain editors.
- **F4** — The representative Analytics view is missing from either host,
  uses independent host-specific domain views/contracts, diverges on the
  declared selection/results, or presents simulated metrics as real.
- **F5** — The identified preview surfaces diverge from the shared scenarios,
  require a competing workbench/mock-server path, or an expected interaction
  only logs an action or leaves a static snapshot unchanged.
- **F6** — A named loading/empty/invalid/rejected outcome is misrepresented,
  validation/rejection loses correction input, or rejection shows acceptance
  or saved state.
- **F7** — A named artifact update fails its expected visible transition,
  conversation text is treated as saved artifact state, or an incoming
  update/away-return silently loses a draft or bypasses its declared
  adjudication.
- **F8** — A declared native interaction uses the wrong/stale room, loses
  member session context, requires another login, or fails the named
  room-action/switch/mount/unmount/return expectation.
- **F9** — Settings substitutes a non-native persistent page, fails the
  selected native interaction, or fails to restore invoking context/focus.
- **F10** — A declared navigation case reaches the wrong context, fails its
  predeclared handling, or depends on a second member navigation lifecycle.
- **F11** — A declared page/host/theme/viewport case obscures required
  content, a primary action or a state message through clipping, unreadable
  presentation or overlapping chrome.
- **F12** — A declared keyboard journey has an unreachable/unlabelled
  control, invisible/lost focus, unusable validation feedback, wrong focus
  restoration or an unintended focus trap.
- **F13** — A declared isolation case activates product fixtures without
  explicit preview/test selection, obscures simulation, supplies fallback
  success after service unavailability, or falsely claims real
  persistence/publication/assistant execution from simulated or Matrix-only
  fixture outcomes.
